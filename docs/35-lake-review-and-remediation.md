## 数据契约与恢复说明

- MySQL 新快照使用 `mysql-char-v2`，非空标量由 MySQL 显式转文本，二进制为十六进制；Schema 保留源类型。旧快照 `json-quoted-v1` 的多余 JSON 引号仅在模型读取时解码，原件不重写。旧模型应建立新候选重新校验后发布，不能直接修改候选文件。
- JSON/API 规范化中的大整数及小数保存为精确文本；原始响应保留解析前字节。下游数值运算必须依类型契约显式转换。CSV 保持文本；Excel 不计算公式，读取已有缓存值；Parquet 的 decimal 保持精确文本。
- 模型 manifest 的 `READY` 表示构建和质量检查通过，活动指针才表示当前发布版本。发布时发现指针已变化则记录 `STALE` 并退出失败；候选和旧版本保留。该保护覆盖并发晚完成；输入业务水位、SQL/dbt 模型与消费权限仍属于未完成工作。
- 本地锁以主机、PID 和令牌识别持有者；可回收同机已退出进程的锁，不把它当成分布式租约。损坏账本或不匹配原件直接失败，不退回空账本重复导入。
- 文件/API 解析失败保留原件和失败清单；重试建立新批次。API 下一页只能同协议、主机及端口，凭证不随 next-link 跨源发送；日期窗口默认北京时间半开时间戳，日期型接口须配置 `window.format: "date"`。
