## 1. 两类实验，不混淆结论

1. 合成数据技术PoC：验证接入协议、SQL加工、日月边界、质量、发布、权限的机制。需确认范围、环境和依赖安装授权；样例口径标为实验规则，不视为正式业务口径。
2. 真实源联调PoC：额外需要源系统接口资料、授权测试环境、历史能力说明和业务验收人。只有脱敏导出时，可验证加工但不能宣称真实接口增量、认证、限流已经验证。

真实源未就绪不阻止经授权的合成实验，但对应验收项必须标记“未验证”，不能整体宣布生产方案通过。

## 3. 建议PoC验收范围

所有建议须在启动记录中确认；PoC只实现验证所需最小纵向链路，不开发完整低代码管理平台。

- 一条DevOps纵向链路：数据读取 → 原始留存 → 明细/历史 → 日/月模型 → 质量门禁 → 数据集发布 → 查询与下钻。
- 明确测试数据粒度、主键和预期结果；黄金样本由指定验收人确认，逐项核对，不仅展示界面。
- 覆盖重复回放、迟到、跨日跨月、重开、团队变化、零分母和历史缺失；不适用项必须说明理由。
- 故障与一致性：同步失败不能误推进检查点，质量失败保持旧版本，旧运行不能覆盖新发布；查询/下钻固定release且受同一权限约束。
- 至少两个隔离身份，证明越权查询及下钻被拒绝；合成身份测试不等于企业SSO集成完成。
- 通用性：增加一个合成的非DevOps主题，例如服务工单，仅增加契约、配置、模型和测试，不修改平台核心。此项不要求再协调真实业务系统，也不证明任意连接器已支持。
- UI仅做运行结果、数据集预览与发布状态等必要页面，采用Naive UI；完整设计系统和页面清单不作为技术PoC启动前置。
- 性能测试单独出具结果：固定硬件、数据量、并发、冷/热状态和目标值；规模未知时只报告观测，不标为生产容量通过。

## 4. 由实施方负责，不要求用户指定补丁版本

- 提交固定依赖候选矩阵，核查Naive UI/Vue/TypeScript/Node与构建工具，以及Java/Spring、SeaTunnel、DolphinScheduler、Python/dbt/adapter/PostgreSQL组合。
- 组件、连接器、驱动及运行镜像的许可证、NOTICE、SBOM与漏洞审查；区分技术核验和组织合规审批。
- 确定最小资源、端口、卷、密钥引用、启动/停止与故障恢复方案；只在授权目标操作。
- 编写可复现实验脚本、脱敏/合成样本、黄金结果和失败场景测试。
- 在短poc分支执行，及时提交；记录SHA、锁文件、镜像digest、测试输出和未验证项。

安装前依赖候选矩阵应交由指定技术/合规负责人按授权流程批准，不把“用户无需选补丁版本”等同于“可自行安装未批准依赖”。

## 5. 启动和退出门槛

### 启动

- 用户确认C01交付方向、C04实验范围、C08环境/操作边界、C09验收责任和时间盒。
- 合成实验：C05未完成业务审批时仅采用明确标注的实验规则；结果不能用于正式报表。
- 真实联调：补齐C02/C03，业务口径由验收人确认；报表联调还需C06。容量验收还需C07的量化目标。
- 精确实验依赖、许可初审和资源方案已记录且获准，然后安装/拉取；不是先使用latest运行再补记录。

### 退出

形成逐项通过/失败/未验证清单、复现步骤、资源观测和风险结论，由指定负责人批准Go/No-Go或限范围继续。失败实验保留；未验证项不能默认为通过。只把经过评审和加固的资产晋级正式开发，不默认删除PoC，也不直接对生产发布。
