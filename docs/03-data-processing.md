# 03 数据加工与指标规范

## 1. 每个模型必须先定义粒度

明细当前态：一来源系统内一个业务对象一行，键通常是 `(source_system, object_id)`。

历史态：一个对象一个版本一行，键增加来源版本或有效起点；事件表以稳定事件ID去重；快照表以对象和快照日唯一。

不能同时声明“一对象一行”和“保留所有版本”。维度历史区间建议使用 `[valid_from, valid_to)`；同一业务键区间不得重叠。

## 2. 接入协议

### 全量初始化与增量衔接

优先使用源系统一致性快照+变更位置；如只支持更新时间接口，先记录起始水位，全量落地后重放重叠窗口并去重，记录不能保证一致性的边界。不要把跨多个请求的扫描称为原子快照。

### 更新时间增量

- 稳定排序使用 `(updated_at, source_primary_key)`，避免同一更新时间跨分页丢失。
- 每批固定上界；窗口采用半开区间；游标、上界和分页进度都入审计。
- 来源存在延迟提交时，配置重叠回读窗口并幂等合并；超窗口迟到通过定期对账/补数处理。
- API无稳定排序、无快照游标时，必须测试分页漂移；必要时增加范围重扫和对象ID对账。
- 数据持久化和批次成功确认后才提交检查点；重复读允许，重复发布不允许。

### 删除和结构变化

更新时间抽取不能自动发现物理删除。选择删除事件、逻辑删除字段、定期主键对账等明确方案。缺少权限或能力时在数据契约中声明不能保证删除同步。

新增可空字段可以按兼容策略接收；字段移除/改类型/改主键阻断受影响模型，原始响应仍可留存并告警。

## 3. 分层规则

| 层 | 责任 | 注意 |
|---|---|---|
| RAW | 原始载荷、来源位置、抽取批次 | 业务字段不改；留存受敏感级别和保留期约束 |
| ODS | 类型/格式标准化、来源当前态 | 保留源状态；不覆盖原始证据 |
| DWD | 明细、事件、维度历史 | 业务去重、状态映射、合法性校验 |
| DWS | 公共周期汇总 | 保存必要分子、分母、样本数 |
| ADS | 稳定报表契约 | 只发布完整版本；维度和度量清晰 |

层级是逻辑职责，不强制五份物理复制。避免多事实表直接关联导致乘法膨胀：先按目标粒度聚合，再关联。一个项目多个团队时需要明确主归属、归属事件或分摊权重，不能无条件复制指标。

## 4. 历史与时间规则

- 存储事件时间、来源更新时间、入仓时间，不能混用。
- 业务日由主题配置时区定义：`[当日00:00, 次日00:00)`，避免23:59:59遗漏小数秒。
- 历史月末状态取下月边界之前最后一个有效状态；发生在次月00:00的变更不计入上月。
- 源系统只有当前态时，从接入起积累快照；接入前历史状态为不可恢复/不完整，不推导成事实。
- 需求完成后重开再完成，必须区分“完成事件次数”和“完成对象去重数”；按期率及周期的统计总体独立确认。
- 团队归属按事件发生时还是当前团队由口径确定；维度更正和实际组织调整需区分并审计。
- 缺陷修复、关闭、重开分别为事件；完成数不能按“现在仍处于完成状态”过滤历史完成事件。

## 5. 周期汇总规则

| 类型 | 日→月/跨维度规则 | 必须保留 |
|---|---|---|
| 可加总值 | 明确可加总维度后求和 | 明细贡献或可追溯分区 |
| 期末状态 | 精确月末快照；缺失标记不完整并补算 | 状态历史/每日完整快照 |
| 比率 | 聚合分子分母后再除 | 同统计总体的分子和分母 |
| 均值 | 总时长/有效时长样本数 | sum_duration、valid_sample_count |
| 去重人数 | 整月/目标维度重新去重 | 原始对象键或可用去重集合 |
| P90等分位 | 从有效明细重算；近似算法需显式标注 | 周期明细或合适统计结构 |

零分母返回NULL并附原因，不默认100%或0%。缺失时长不能计入均值分母。进行中对象无结束时间，不以0时长混入已完成样本。

一期不做任意指标表达式运行引擎；指标目录关联经版本管理的SQL模型、口径和测试。禁止声称所有指标都能由配置自动正确生成。

## 6. DevOps首批样例范围

待业务签字的建议指标：新增需求、完成需求事件、完成需求对象数、期末未完成需求、有效交付周期均值、新增缺陷、关闭缺陷事件、期末未关闭缺陷、有效缺陷关闭周期均值。按期率需可追溯的计划截止时间后再纳入。

建议模型：项目/团队历史维度、需求当前态及状态事件、缺陷当前态及状态事件、对象日末快照、项目/团队日汇总、月汇总、报表日报/月报/下钻明细。

下钻基于指标口径、时间窗、维度归属和发布版本重放筛选，不能只按一个通用metric_value字段代替全部贡献关系。

## 7. 日/月调度

日任务：固定数据水位 → 接入 → 标准化 → 历史和事件加工 → 质量 → 日汇总 → 月内累计重算 → 对账 → 数据集发布。

月任务：等待全部必要日期和来源就绪 → 重算月范围指标及月末快照 → 对账 → 发布。未结束月份标识MTD；月份完整性不由“任务执行成功”推断。

T+1截止时间、允许迟到窗口、月结宽限期均参数化，待源系统SLA确认。月结采用不可变发布版本而非永远锁死；修正需新版本及审批。

## 8. 补数与幂等

- 逻辑运行键：工作流版本、业务时间区间、输入水位/修订版本；每次重试分配attempt。
- 接入使用稳定来源键合并；历史事件按事件ID/确定性组合键去重，哈希不能单独证明业务唯一性。
- 加工使用隔离版本构建或事务内分区替换；禁止裸露的“删分区后逐行插入”。
- 补数计算受影响的日期、月份、下游模型及维度历史范围；不只重算导入当日。
- 同一目标区间限制并发发布；发生旧运行晚完成时，使用版本检查拒绝覆盖较新发布。
- 发布记录保存代码版本、规则版本、输入水位、维度版本和原始保留范围；过期源数据缺失时明确无法完整重放。

## 9. 数据质量与对账

硬失败：缺业务键、主键冲突无法判定、历史区间重叠、关键来源不完整、金额/数量对账超阈值。软失败：经业务批准的非关键维度缺失等。

质量异常保留规则、来源键、批次、错误原因和处理状态；未知维度可使用UNKNOWN并标记，不默认丢弃整条业务事实。是否隔离由规则的业务影响决定。

对账采用相同时间水位、状态口径和统计范围：源候选数 = 有效入仓数 + 已解释排除/异常数；明细贡献与汇总一致。存在去重、取消、权限过滤等条件时不能要求不加解释的源表总数等于报表总数。
