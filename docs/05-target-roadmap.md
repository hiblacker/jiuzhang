# 05 最终目标路线图

最终架构由业务需求和运行指标驱动扩展，不按组件数量衡量成熟度。以下周期是一期验收后的规划区间，需重新估算和审批。

| 阶段 | 建议周期 | 核心交付 | 进入/退出条件 |
|---|---|---|---|
| 一期：通用报表闭环 | 18周基线+外部缓冲 | 通用契约、接入加工、质量、日月数据集、DevOps首主题 | P0验收、合成第二主题、不改核心 |
| 二期：真实多系统 | 8–12周 | 第二/第三业务系统、第二接入方式、公共维度映射、跨主题数据集 | 明确系统和负责人；跨系统归属/主键对账通过 |
| 三期：治理与服务规模化 | 8–12周 | 目录/血缘整合、影响分析、订阅/导出、授权申请、发布自动化 | 模型数量和协作规模形成真实需求；权限与发布可审计 |
| 四期：按需实时与容量扩展 | 另行PoC定期 | CDC/流处理、分析存储、资源隔离、成本/异常监测 | 现有T+1无法满足业务或压测瓶颈明确 |

## 1. 能力成熟度

| 领域 | 一期 | 最终目标 |
|---|---|---|
| 接入 | 一种生产连接器+扩展协议 | 多连接器；批量/CDC/流按需 |
| 加工 | SQL优先、受控任务 | 标准算子、SQL、隔离扩展插件 |
| 模型 | 主题明细/历史/汇总 | 跨域公共维度、业务语义协同 |
| 指标 | 口径登记+版本化SQL | 受控语义层、可复用计算规范 |
| 调度 | DAG、参数、重试、补数 | SLA/资源策略、跨域依赖、规模化运维 |
| 数据集 | 报表查询、下钻、发布 | API、文件、订阅、自助取数 |
| 治理 | 必要元数据、表级依赖、质量 | 字段血缘、资产目录、责任闭环 |
| 安全 | 组织权限、隔离账号、审计 | 策略统一、多环境/组织治理 |
| 可靠性 | 备份、恢复、保旧发布 | 按业务RPO/RTO设计高可用与灾备 |

## 2. 通用性扩展协议

连接器声明来源类型、分页/游标、删除支持、模式变化行为和一致性等级；执行器声明任务提交、查询状态、取消和日志读取；存储适配声明合并写入、分区、发布可见性和权限能力。

扩展能力必须显式标注支持/不支持，不能用统一接口隐藏数据可靠性差异。平台不强制所有引擎具备相同事务和CDC语义。

## 3. 引入新组件的门槛

- 分布式分析数据库：真实查询扫描/并发指标超过既有存储的可优化空间。
- CDC/实时：已确认可量化的时效需求，且源系统允许日志读取与持续维护。
- 元数据目录：多个主题/团队的发现和影响分析需求已超过最小目录。
- 外部质量框架：规则规模、执行结果管理或跨引擎需求确实超过当前SQL校验。
- 高可用：可接受恢复时间短于单实例重建/恢复时间，并有明确预算和运维人员。

每次引入须有ADR、PoC、固定版本、升级策略、安全和许可证检查、运维责任人和回退路径。

## 4. 不纳入默认最终范围

机器学习平台、数据交易市场、全组织实时改造、所有业务主数据写回和复杂多租户计费不是必达项。可以作为独立产品扩展，不能挤占报表数据可信交付的目标。

## 5. 最终验收观测指标

跟踪新主题接入周期、核心代码变更次数、质量问题发现到修复时长、数据集SLA达成率、查询P95、历史重放成功率、未经授权访问拦截、单位处理/查询成本。

基线在一期试运行建立；后续设改进目标，不在缺乏数据时编造收益百分比。
