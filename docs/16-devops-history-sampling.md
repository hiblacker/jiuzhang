- 工作包：验证操作历史的状态变化结构、缺陷关联及项目成员历史候选；不是全量历史审计或正式指标计算。
- 授权：在上轮已明确提出“最多5个对象、每对象最多20条日志”的下一步之后回复“继续”，本轮按该范围执行测试库业务采样。连接JSON中的metadata_only/allow_business_row_samples及TLS配置不修改；工具必须另传运行级业务采样开关，TLS例外仍单独显式传入。
- 写范围：tools/、tests/、docs/、README.md；源数据只读，私有证据只写入被Git忽略的work/。
- 验收：限定字段与行数、单连接、SELECT不超过15秒、验证实际TLS和只读会话、原配置哈希不变、无凭据/原始业务内容入Git、测试和文档检查后提交。

## 1. 固定采样边界

1. 仅配置database对应的源库，不跨库补历史。复用第14、15号记录中的固定本地MySQL客户端镜像和隔离措施；不安装依赖。
2. 按主键顺序选最多2条STORY和3条DEFECT，仅ID、项目、类型、状态代码、删除标志及必要时间；属于方便抽样，不是随机、最新或代表性样本。
3. 每对象按已有项目+对象索引取最多20条操作日志。不对整张日志表排序；采样不保证完整生命周期或时间连续，不用字符串ID裁定同时间先后。
4. 最多选样本涉及的1个项目，按已有项目+时间索引取最早20条项目变更记录。只提取事件/字段类型的结构特征、通过ASCII代码格式限制的枚举值和前后值形状，不提取人员、标题、描述或原始前后值。
5. 操作类型仅保留通过ASCII代码格式限制的枚举值（不适用于内容/姓名字段）。日志正文只在服务端计算长度、JSON合法性、固定路径存在性及固定状态词命中标志，不返回正文。固定词命中只是文本证据，不代表已解析出前后状态或批准了枚举映射。
6. 原始ID、必要时间及采样证据仅本地保存；共享文档只记录聚合结论。不存在的日志不解释成“从未变更”。达到LIMIT表示可能截断，不报告完整性。
7. 只运行固定SQL模板；标识符须通过本地元数据校验，值经PREPARE绑定。禁止任意SQL入口、全库计数、源DDL/DML、压测和NAS部署。

## 2. 结果

### 已执行事实

- 完成5次成功测试连接：两轮相同种子选择、三轮同对象历史投影/复测。唯一集合始终为5个对象、20条操作历史A和20条项目变更历史B；已离线比较ID集合，重复投影不累计为新样本。
- 所有会话确认TLSv1.3、只读标志1、SELECT上限15000ms；原连接文件哈希不变，临时凭据及调查容器均清理。未部署NAS、未写源库、未压测。
- 两个STORY样本都是子任务类型；3个DEFECT样本都有对应日志，按项目+对象ID关联后，日志对象类型也与主记录一致。此前“注释只列需求/任务”不能作为排除缺陷的依据。尚未抽到需求主类型样本。
- 20条对象日志中7条为状态更新操作（任务5条、缺陷2条），不是所有操作都代表状态变化。
- 7条状态操作内容均不是JSON对象；其中3条与固定状态白名单逐字节相等，其余4条尚未映射。这里只验证单值标签存在，未验证它表示新值，也未恢复旧状态、重开或完整生命周期。
- 全部20条对象日志内容包括3条NULL、16条非JSON文本和1条JSON整数。开发时修复了MySQL JSON布尔值被当作数值1统计的缺陷，增加回归测试；本节以最终复测/原始证据重新汇总为准。
- 5个对象的实际开始时间均缺失；2个任务有实际结束时间，3个缺陷均无实际结束时间。不能把当前起止差直接当可靠周期，缺失不填0。5个样本都有创建时间，但不代表全表完整或时区语义已确认。
- 所查1个项目的前20条变更中19条为项目成员事件候选，出现两种操作代码，尚未确认新增/移除语义。20条前后值均为空字符串，不能仅用这两个列恢复成员有效期。成员标识是否在事件ID/扩展信息中，本轮未读、未验证。

### 边界和缺口

对象日志各组返回6、7、1、5、1条，未触及20条上限，但仍不能证明全历史完整；日志可能归档、软删除或存在其他通道。项目历史返回20条，明确视为可能截断。三轮查询不是一次跨轮一致性快照；本批ID集合一致也不证明其他字段在未来不变。

源DATETIME的业务时区、时钟偏差、日志保留范围、同时间顺序、重开规则、软/硬删除和团队业务定义仍需独立确认。项目成员事件不等于组织团队历史。

## 3. 对数据中心实施的影响

| 目标 | 可继续的工作 | 当前不得自动启用 |
|---|---|---|
| 流量计数 | 创建流量模型与合成事件统计；定义对象/事件粒度、去重键与时间窗口 | 未批准状态字典和日志语义前的真实完成/重开回算 |
| 周期耗时 | 合成数据验证首次/最终完成及分段周期；保留有效样本数和质量原因 | 用缺失起止补0、把当前结束当每次历史完成、直接平均日均值生成月均值 |
| 期末存量 | 从可信基线和连续事件计算，或从接入日起建设日末快照 | 用当前状态回填过去月末、缺失快照当零 |
| 团队归属 | 项目维度先行；继续验证成员标识与有效期 | 把当前团队映射到历史，或将多团队连接后的行数当对象数 |

通用核心仍只接受有来源和粒度的对象、状态观察/已验证事件、关系有效期、快照及数据集契约。DevOps日志代码、标签映射和字段关系保留在领域层；调查脚本不是正式接入适配器。

下一工作包为合成数据技术PoC的依赖版本/许可清单和黄金样本契约，然后实现最小可运行纵向链路；真实历史缺口不阻塞合成实验，但会阻止未经验证的历史报表发布。额外负例必须包含：日志为单状态标签、未知状态、JSON标量而非对象、缺失开始时间、空成员前后值。还须覆盖重复重放、迟到、重开、团队变更、上海日/月边界、缺失快照、月报B修订和旧任务不得覆盖新发布。

## 4. 工具与复现

复用已批准的本地缓存 `mysql:8.0.43` 客户端镜像版本标签（见[14号记录](14-mysql-test-discovery.md)）；源为8.1.0；本机Node为22.23.2；不新增第三方依赖。不代表该客户端已通过正式商业交付的再分发审核。

~~~powershell

node tools/mysql-discover.mjs --sample-devops-seeds --allow-test-business-samples --allow-unverified-test-tls
node tools/mysql-discover.mjs --sample-devops-history --allow-test-business-samples --allow-unverified-test-tls
~~~

- [领域采样模块](../tools/devops-history-sampling.mjs)：固定表/字段投影、元数据和索引校验、参数绑定、5对象/每组20条限制、正文形状与白名单状态标志。
- [客户端入口](../tools/mysql-discover.mjs)：默认仍只读元数据且严格验证证书身份；业务采样与TLS例外没有隐式开启，禁止任意SQL参数或混用采样/元数据阶段。
- 先读被忽略的本地元数据字典，再生成固定SQL；种子引用绑定配置指纹、源库指纹和文件SHA-256，拒绝路径逃逸、待完成引用、配置改变和样本文件损坏。重新运行种子阶段会使旧引用失效，失败后需成功重跑种子阶段，不编辑引用绕过校验。
- 最终两轮保留独立运行报告和SQL/采样模块SHA-256。结果摘要明确为有限方便样本，不把查询成功等同于全历史完整。
- 私有报告为本地work/source-history-sampling-report.md；原始ID/时间/枚举、原始投影及SHA-256证据清单均在work/且不提交。原文、人员及标题字段未返回。
