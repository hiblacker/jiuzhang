# 01 产品范围与最终目标

- 产品名称：九章 · Jiuzhang；完整名称：九章数据平台 / JiuzhangData Platform。
- 基线日期：2026-09-10
- 状态：待项目负责人、数据负责人和报表负责人评审

## 1. 已确认需求与限制

已确认：建设通用数据中心；首个来源是科技业务条线 DevOps 一站式研发流程平台；源系统没有可直接使用的日/月指标；当前消费方是报表系统。

尚未确认：DevOps 产品/版本、数据库和接口、历史变更记录、数据规模、报表连接协议、技术栈、基础设施、研发人员和上线日期。本文对这些内容只提出建议，不假定已经具备。

## 2. 职责边界

| 主体 | 负责 | 不负责 |
|---|---|---|
| 业务系统 | 交易和过程记录、事件/接口输出、业务源头修复 | 在源系统为每张报表重复开发加工逻辑 |
| 数据中心 | 接入、标准化、历史、加工、周期计算、质量和数据集发布 | 替代业务交易系统、默认改写源数据 |
| 报表系统 | 展示、筛选、交互、在允许范围内汇总 | 重复定义核心口径、绕过数据权限查内部表 |
| 业务负责人 | 指标定义、归属规则、质量豁免和验收 | 将口径决策完全交给开发人员 |

## 3. 用户角色

平台管理员管理连接和执行资源；数据开发维护模型与 SQL；数据负责人审核口径和质量；发布审批人批准生产变更；报表开发消费数据集；数据消费者按权限查询；运维处理运行异常。

一期可以合并岗位，但生产变更、查询授权和审计仍应区分动作及操作者。

## 4. 一期 P0：必须闭环

- 数据源登记、凭证引用、连接测试；实现与 DevOps 条件匹配的一种主连接器。
- 全量初始化、增量检查点、批次审计、原始留存；明确删除检测边界。
- 主题与模型登记、SQL 版本、日期参数、依赖编排、重试和补数。
- 原始、标准明细、汇总、应用逻辑分层；允许简单链路合并物化层。
- 事件和快照机制；可获得范围内的团队归属历史。
- 首批 8–12 个已签字的指标；团队/项目日报、月报及必要明细。
- 非空、唯一、枚举、引用、时间逻辑、对账和质量门禁。
- 数据集契约、不可变发布记录、原子可见性、只读查询、数据截止时间。
- 组织/团队权限、查询审计、下钻授权、失败告警、恢复说明。
- 第二业务主题的合成样例验证通用性，不依赖第二业务系统上线。

## 5. P1：按数据与资源条件追加

任务工时、代码评审、流水线和发布主题；第二种正式接入协议；基础配置算子；更多可视化编辑；字段级血缘；统一指标目录检索。

**历史正确性、对账、权限、发布一致性、核心下钻不是可后置的装饰功能。** 缺少源历史时应缩小可承诺的数据范围，而不是伪造历史。

## 6. 一期明确不做

通用表达式编译器、全功能拖拽 ETL、全部连接器、跨地域多活、全量实时湖仓、机器学习特征平台、跨租户 SaaS 计费、自助任意 SQL 查询、对源系统回写。

## 7. 最终目标

提供连接器扩展、批流按需融合、多主题公共维度、可测试的 SQL/算子加工、周期统计、目录与血缘、质量闭环、数据集/API/订阅服务、环境隔离与生产变更控制。

最终目标是能力边界，不表示所有组件必须部署。只有实际业务、容量或治理需求触发时才引入对应能力。

## 8. 通用性验收

新增“销售”合成主题，包含订单增量、客户维度、日金额、月去重客户数、月末未结订单及报表数据集。不得修改平台核心代码；允许新增主题配置、模型、SQL、测试及数据集授权。记录开发时间和缺失扩展点；不以固定时间的未验证承诺替代验收。
