# 整库接入：真实源发现与首批执行依据

## 1. 已完成的实际操作

2026-09-15，用户明确允许对所提供测试源采用 TLS 例外：仍强制加密，跳过服务器证书身份校验。范围包含该测试源的调查与入湖，不覆盖其他来源或正式环境；不允许源库写入。授权按连接配置摘要记录到本地 Git 忽略文件，默认严格 TLS 配置保持不变。

使用本机已有 MySQL CLI 9.7.1，经认证版本查询返回 MySQL 8.1.0。实际会话确认 TLSv1.3、只读标志和 15 秒 SELECT 上限。查询限定于用户指定库的表、列及索引元数据，未扩大到其他可见库；无 DML、DDL、业务行读取或全表 COUNT。

来源包含字符、文本、整数、日期/时间、Decimal 和 Float 类型。本次发现没有证明业务键、更新时间和删除规则的实际语义，不能直接据字段名开启增量或构造历史。

## 2. 首次接入计划已经按全表生成

157 张表均已进入本地首批计划，状态为待抽取器验证；每表记录字段、列序、主键、Schema 指纹、估计规模与抽取策略。私密结构与逐表计划保存在 Git 忽略目录，不提交真实表名和字段清单。

- **首次全部采用 FULL_SNAPSHOT。** 3 张无主键表同样全量接入，不自动排除，不凭行号构造业务键。
- **日常增量尚未批准任何表。** 在首次全量之后，逐表验证修改时间、提交顺序、删除表达和索引条件；不将“有时间字段”当作可靠增量保证。
- **整库同一时点一致性需要抽取器验证。** 全部 InnoDB 为一致性读取提供条件，但现有 SeaTunnel 多表任务是否共享同一快照尚未证明。若采用独立连接，必须显式标为表级快照集合。
- **类型保真先于格式转换。** BigInt、Decimal、Float、空值、日期与文本需有可往返的编码和测试。原始层保存来源字段，不执行指标计算、业务筛选或表间关联。
- **结构变化不静默接受。** 批次固定引用清单版本；抽取前后复核 Schema，破坏性变化使批次失败并重新发现。

## 3. 整库原始快照执行器（已落地，兼作验收契约）

本工作包依照[主实施方案](31-warehouse-implementation-plan.md)，允许修改独立 Worker/接入适配、版本迁移、合成测试与运行文档。凭证、真实结构和数据输出保持本地隔离；不改写源库、不重写已执行迁移、不部署生产或远程推送。

### 输入

受控来源引用、已生成的清单及计划版本、系统批次 ID、唯一 attempt、可用湖区根目录和存储限额。TLS 测试例外必须匹配该测试来源的授权引用，不能变成通用默认关闭校验选项。

### 必需实现

1. 逐表流式读取所有计划字段，封存类型明确的原始分片及 Schema。
2. 持久化表清单、分片字节/行数与哈希；空表也生成清单。
3. 共享快照和表级快照两种语义明确区分；快照失效后重新执行对应单元，不能接着主键续读冒充原快照。
4. 全部必需表完成才提交系统清单；失败、取消或失去租约不推进最新完整批次。
5. 支持同一逻辑运行重复触发及失败尝试隔离；旧 Worker 不得覆盖新批次。
6. 加入每日窗口账本、缺失识别与补跑，记录实际采集时点；当前数据不能冒充过去快照。

### 出口条件

157 张表在同一固定覆盖清单下有明确结果，所有必需项成功才宣告整库完成；原件、Schema、清单可校验及重放；重复运行、落盘失败、连接中断、进程重启、无主键和空表均经过测试。实际抽取量、时间范围及源库负载必须由运行记录提供。

本记录保留发现阶段的历史边界；随后已按该清单完成真实全量和一个每日窗口。运行批次、逐表哈希与幂等证据见[入湖实现与实际验收记录](34-lake-implementation-evidence.md)。
