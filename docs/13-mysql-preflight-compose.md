2026-09-10本机执行[预检工具](../tools/mysql-preflight.mjs)，仅从本地配置读取目标，不打印主机、用户名、密码或数据库名。

- 配置JSON解析成功，必需字段已填写；配置要求TLS和证书校验，未配置专用CA路径。
- 账号名称匹配常见管理员名称；尚未登录，未读取GRANT，不能把名称检查当成权限审计。遵循已约定专用只读账号的准入要求，本轮未使用该凭证尝试认证。
- 单次TCP连接收到MySQL协议10握手；提取数值版本8.1.0；服务端握手声明支持TLS。
- **没有发送账号、密码或任何应用层客户端字节，没有TLS协商，没有SQL。** 握手版本未经认证，不等同于执行SELECT VERSION()；TLS能力标志也不等于证书验证通过。

工具只依赖Node内置模块；限制连接10秒以内、握手缓冲4KiB，输出固定错误类别，不输出服务器原始banner、握手盐或原始异常。原始连接文件保持不变；本地脱敏预检结果位于被忽略的work/。

## 4. 元数据SQL范围

首轮查询版本、可见schema、STORY/DEFECT所在schema及按名称匹配的历史候选表。每组最多200行，达到上限后记录结果不完整，使用稳定分页继续，不自动放大超时。

列/索引/约束跟进以查到的schema和表名作绑定值，使用固定information_schema查询。不执行SELECT *、全库COUNT(*)、EXPLAIN ANALYZE、任意过程、DDL或DML。表名未匹配时，再依据受控范围内的列名/注释逐步扩展调查；名称匹配本身不证明历史语义。

原始结构、库名、注释和任何采样结果默认只存本地work/。入Git仅放通用工具、合成测试、脱敏结论；真实字段映射按约定脱敏/确认后提交。

## 5. Compose选择与验证方案

PoC优先以PATH中的v2.20.1入口作为兼容目标，先确认其实际绝对路径和执行账号，再将入口及版本记录到发布清单。v2.40.3保留为备选，不因为它更高就默认以root部署，也不修改全局PATH、软链接、插件或现有容器。

这是建议目标，尚未验证任何Compose部署文件；如后续发现必需功能或安全问题需要升级，先提出理由并选择同一入口统一部署。Engine 24.0.2与两种Compose的实际服务端API连接、配置和镜像能力均需测试，版本数字不能代替兼容性验证。

部署前流程：

1. 由用户或获授权的操作方式核查选定入口的version、docker version服务端信息、资源和存储；无需把用户加入高权限组或给root口令。
2. 对锁定依赖和镜像生成Compose文件，仅使用所选目标验证过的字段。
3. 使用同一入口执行config --quiet验证解析；避免输出展开的配置，因为可能包含环境变量里的密钥。
4. 经确认在专用项目名、专用卷目录及端口执行启动，验证健康检查、数据库持久化、日志脱敏和停止/恢复。
5. 同一项目的up、ps、logs、stop等管理统一使用选定入口；不使用不明确PATH导致两个版本交替管理。

不得直接在用户NAS执行示例命令或猜测项目目录。存储类型、空闲空间/内存、Container Manager套件信息和实际部署身份仍待核查。
