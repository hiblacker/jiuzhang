## 1. 本轮明确授权

用户在说明无可提供证书后，明确确认“仅本次测试库调查使用REQUIRED：强制TLS加密，不验证服务端证书身份”。该例外不用于正式接入，不把PREFERRED或DISABLED作为回退。

工具默认仍为VERIFY_IDENTITY。每次使用例外必须显式传入--allow-unverified-test-tls；例外仅覆盖当前本地测试源的发现流程，调查结束后不再沿用。用户JSON中的TLS配置保持不变，不持久化关闭校验。

复用[14号记录](14-mysql-test-discovery.md)固定的缓存客户端镜像、资源限制、凭据隔离和清理措施。新增会话Ssl_cipher/Ssl_version与只读/超时检查；不请求额外系统权限。MySQL官方说明REQUIRED要求加密，Ssl_cipher可用于核查会话是否加密：<https://dev.mysql.com/doc/refman/8.0/en/using-encrypted-connections.html>（仅官方参考链接；2026-09-10浏览工具未返回可用正文，不作为本轮已核验的在线证据；以下会话事实来自本地实测）。

## 2. 发现结果

### 已执行事实

- 成功完成4次受控数据库连接；经认证的版本SQL返回8.1.0，四次会话均确认TLSv1.3、只读标志=1和SELECT超时15000ms。只读会话/事务设置及information_schema查询已真实执行。
- 可见9个schema，两个schema均有STORY/DEFECT；以用户连接文件指定的database为优先调查源，不按名字或行数猜测环境。两个源的结构有差异，不自动合并。
- 检查21个“schema+table”对象、425列及索引，未返回外键记录；这不证明不存在应用层关系，也不涵盖未选表。
- 初始范围查询与三轮明细/扩展目录查询均未命中200行上限。完成性只针对已执行的限定查询，不是全库审计，更不是历史数据完整性保证。
- 明细结果为326、275、104条元数据记录，包含目录重复项，不能简单相加当唯一字段数。原始TSV/JSON与SHA-256证据清单保存在本地work/。
- 没有读取业务表行或日志正文，没有全库COUNT(*)、DML/DDL、源库压测、权限修改、NAS登录或部署；临时凭据和容器已清理。

### 脱敏结论

真实库名、未获提交确认的完整字段映射、注释和真实数据字典不入Git；本节使用对象角色描述，具体表名与字段见本地报告。

| 主题 | 结构发现 | 不能据此宣称 |
|---|---|---|
| 主对象 | STORY/DEFECT存在主键、对象类型、项目关系、粗/细状态与创建/更新/实际起止时间 | 注释枚举不等于实际取值，当前起止时间不等于每次历史处理周期 |
| 操作历史A | 有对象关联、类型、操作、内容和时间，但没有独立状态前后值列 | 尚未确认可解析状态变更或覆盖缺陷 |
| 项目变更历史B | 有事件/字段类型、原值/目标值与事件时间 | 项目成员历史是否完整、是否能恢复业务有效区间未验证 |
| 通用事件候选C | 另一源中存在前后值及业务对象结构 | 不得跨源拼接弥补当前源历史 |

| 展示/迭代统计 | 源中已有展示表和迭代计数表 | 没有已确认的日/月粒度、快照键或口径，不能直接当日报/月报事实 |

表估计行数来自信息模式，仅用于粗略调查参考；不是实际COUNT，不据此修改百万历史总量/每日新增几千条的用户输入。

## 3. 对一期设计的落地影响

1. **先完成项目维度，再验证历史团队维度。** 项目归属结构较明确，但候选join没有外键保障，仍需验证孤儿记录、多对多与历史归属。不会将现在团队直接套入历史报表。
2. **三类指标拆开验证。** 新增流量可先检查创建时间；完成/重开流量与多段周期需要可靠事件；接入前期末存量需要期初基线和连续事件链。缺少历史时只能从接入日起留存，不伪造过去结果。
3. **状态映射放DevOps领域模型。** 按项目、对象类型、流程节点确定映射，平台核心不写死源状态码。注释只能产生待验证候选。
4. **增量接入仍有性能门禁。** 主对象有更新时间，但所查索引没有以更新时间开头的索引；没有进行EXPLAIN或CDC权限核验，不默认变更源库索引。先验证受控分页、更新时间/删除语义和源库负载，再选择批增量或经批准的CDC。
5. **既有报表表只作对账候选。** 明细与展示表时间精度不完全相同；日/月加工从批准粒度的标准事实出发，不把日存量、均值等简单相加。
6. **真实字段契约仍未冻结。** 先用明确标注的合成事件/关系区间验证幂等、迟到、重开、缺失快照和发布一致性；源映射验证后再连接真实抽取。不存在因找到DevOps表而将平台改成专用指标中心的决定。

## 4. 本地交付物与复现

在项目work/下保存：

- source-discovery-report.md：结构事实、候选关系图、历史缺口与受控采样建议。
- mysql-source-dictionary.md / mysql-source-dictionary.json：21个所查对象的结构字典。
- mysql-discovery-evidence.json：4次成功连接的输出文件、摘要与会话核验记录。
- mysql-initial-targets.json：真实schema与首轮选择，仅本地。
- mysql-metadata-*.tsv / *.json：原始元数据输出；mysql-discovery-result.json是最近一次运行摘要，不能替代历史证据清单。

调查工具只接受固定操作，既不接收任意SQL文件路径，也不接受任意查询语句。明细选择从忽略的work/mysql-metadata-targets.json读取，schema/table值通过服务端PREPARE/EXECUTE参数绑定，SET绑定值使用十六进制编码避免转义模式差异；一次最多10个schema、20个目标表，每个固定查询上限200行。

在项目目录执行：

~~~powershell
# 默认严格证书校验，不会自动降级
node tools/mysql-discover.mjs
# 仅本次已授权调查；不得复用到正式部署或无人值守任务
node tools/mysql-discover.mjs --allow-unverified-test-tls
# 先准备/审核本地元数据选择清单，只允许schema/table值
node tools/mysql-discover.mjs --allow-unverified-test-tls --details
~~~

目标选择格式为schemas数组和targets数组，每个target只含schema/table；catalog_only=true允许空targets以仅搜索目录。工具没有自动全库扩张、无界分页或业务行读取模式。当前源业务样本设置仍是metadata_only=true/allow_business_row_samples=false；本轮TLS例外不改变该限制。
