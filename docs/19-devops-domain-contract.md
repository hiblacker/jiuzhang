# 19 DevOps 首主题域契约与首条真实接入边界

- 日期：2026-09-14。
- 状态：部分规则已确认，状态码和历史归属仍待受限调查/业务确认；不是已发布的数据集，也不是正式源库全量接入授权。
- 目的：把 DevOps 作为通用数据中心的第一个主题域，限定首条真实源接入可实现的范围，避免把调查到的表结构、单值日志或当前态误写成已确认的业务事实。
- 证据边界：本契约只基于[源库元数据发现](15-source-metadata-findings.md)和[限量历史采样](16-devops-history-sampling.md)。真实物理字段映射、样本行、对象 ID、时间和枚举仅保存于被忽略的 `work/`、`secrets/`，不进入 Git。
- 状态字典核查：2026-09-14 通过受限只读查询成功，返回 201 组 `NODE_STATUS` 记录和 48 组对象状态样本；字典查询达到固定上限，真实结果仅保存在本地 `work/`，不构成完整枚举。

## 1. 主题域定位

DevOps 主题域通过领域映射向平台提供对象、状态观察、已验证事件、关系有效期和快照；平台核心只处理稳定对象键、批次、水位、版本、质量和发布。`STORY`、`DEFECT`、状态码、日志标签及团队关系不能进入通用接入或指标执行模块。

首个来源为用户指定 MySQL 8.1.0 测试库。当前调查只使用固定 SQL、单只读连接、15 秒限时和受限采样；正式接入必须使用受控的凭证引用和严格 TLS 证书校验。测试阶段允许的 TLS 身份校验例外不能带入正式环境。

## 2. 逻辑对象与最小粒度

| 逻辑模型 | 粒度和稳定键 | 当前来源证据 | 首期处理状态 |
|---|---|---|---|
| `devops_object_current` | `(source_system, object_type, object_id)`，一对象一当前态 | `STORY` 和 `DEFECT` 有对象标识、项目关联、状态与生命周期时间候选 | 可设计，物理字段映射待冻结 |
| `devops_status_observation` | `(source_system, object_type, object_id, observed_at, source_log_id)` | 已找到对象操作日志；样本为单值标签、NULL 或文本 | 仅 RAW/ODS 留存，不能自动升格为状态变更事件 |
| `devops_project_relation` | `(source_system, object_id, project_id, valid_from)` | 对象存在项目关联候选 | 可先按项目维度加工；关系基数待确认 |
| `devops_team_membership` | `(source_system, member_or_project_id, team_id, valid_from)` | 有成员事件候选，但样本前后值为空 | `BLOCKED`，不能还原历史团队有效区间 |
| `devops_object_snapshot` | `(source_system, object_type, object_id, snapshot_date)` | 可从正式接入日开始积累 | 接入基线完成后可建设；接入日前不可倒推 |

已确认 `STORY.TYPE=0` 表示需求、`STORY.TYPE=1` 表示任务；任务的 `PID` 指向所属需求。正式领域映射使用 `requirement`、`task`、`defect` 三类 `object_type`，并以 `(source_system, object_id)` 作为对象键、以 `PID` 建立任务到需求的父子关系。仍需在真实接入前核验 `DEFECT.TYPE` 及其他类型取值，不得把 `STORY` 其他值猜测成业务类型。

`DELETE_FLAG=0` 表示未删除，`DELETE_FLAG=1` 表示已删除。删除对象保留 RAW/ODS 来源证据，并由领域规则决定是否从流量、存量和周期统计总体中排除；在该规则确认前不得静默丢弃。

## 3. 首条真实接入的受限范围

### 3.1 可实施内容

1. 受限只读抽取 `STORY`、`DEFECT` 的当前态，连同来源名、抽取批次、来源更新时间、入仓时间和原始载荷进入 RAW。
2. 在 ODS 生成一对象一行的标准当前态；重复回读按稳定来源键幂等合并，保留来源状态而不映射为完成或关闭。
3. 每日保存接入后的对象快照，并记录快照完整性、输入水位、模型版本和批次。首个成功且通过完整性检查的批次是历史存量的可追溯下限。
4. 将创建时间的对象流量做为隔离的候选计算结果，包含对象键和贡献明细，等待取消、删除及对象分类规则确认后才发布给报表。

### 3.2 明确不实施或不发布的内容

- 不以单值日志标签推断旧状态、新状态、完成、关闭或重开。
- 不从当前实际开始/结束时间回填历史完成事件或周期耗时；当前样本的开始时间缺失，缺失值不能补零。
- 不向接入日前的日末/月末倒推期末存量；缺失快照必须标识为不完整，不能为零。
- 不按当前团队回填历史团队归属，也不把项目成员事件候选直接作为有效区间。
- 在删除语义未确认前，不将未被增量读取到的对象解释为删除、关闭或不计入。

## 4. 增量、快照与月度处理

`UPDATE_TIME + 来源主键` 是当前的**候选**增量游标，不是已批准的正式策略。实现前必须验证字段业务语义、时区、精度、空值比例、稳定排序能力和索引。若通过验证，批次固定开始前的上界，按稳定键排序，以半开区间和可配置重叠回读读取；成功持久化 RAW、ODS、质量结果后才推进检查点。重叠数据按来源键幂等合并，超出重叠窗口的迟到数据由对账或明确补数处理。

日报运行目标维持 `Asia/Shanghai` 的 T+1 06:00；实际抽取开始时间、来源 SLA 和允许迟到窗口尚未确认，因而该目标不是服务等级承诺。业务日和业务月统一使用 `[start, end)` 半开区间。

平台默认时间角色如下，正式字段映射仍需源系统负责人核验：`CREATE_TIME` 是对象首次创建时间，用于新增流量；`UPDATE_TIME` 是来源当前记录最后更新时间，用于增量游标，不作为业务事件时间；`ACTUAL_BEGIN_TIME` 是实际工作/处理开始时间；`ACTUAL_END_TIME` 是实际完成/结束时间。实际开始或结束为空时不补零、不用当前时间替代，并从对应周期耗时分母排除。若字段在源系统中的含义不同，必须通过字段契约版本修订后再加工。

月报采用用户已选的 B 方案：结账前可滚动重算，结账后仅通过审批发布新修订版本，既有发布版本不可覆盖。实施方暂定每月第 5 个自然日 06:00 生成结账候选版本；由数据中心负责人审批，涉及指标口径、历史归属或删除规则的修订追加业务负责人审批；结账后允许回溯最近 3 个已结账月份。该安排是可配置的实施默认值，不是用户最终审批。重开月必须生成新修订版本并保留旧版本、原因、审批人和影响范围。

## 5. 指标可发布性

| 指标类别 | 候选指标 | 当前状态 | 发布前的阻断条件 |
|---|---|---|---|
| 流量计数 | 新增需求、新增缺陷 | `CONDITIONAL` | 对象分类、创建时间语义、取消/删除规则、去重键确认 |
| 流量计数 | 完成需求、关闭缺陷、重开次数 | `BLOCKED` | 状态字典、日志值方向、事件时间与同刻排序规则确认 |
| 周期耗时 | 需求交付周期、缺陷关闭周期 | `BLOCKED` | 可信的每段开始/结束事件或经业务批准的补值规则；当前样本不能满足 |
| 期末存量 | 期末未完成需求、期末未关闭缺陷 | `CONDITIONAL_FROM_ONBOARDING` | 完成/未完成状态映射、删除规则、成功基线和连续完整快照；仅从接入日开始 |
| 组织维度 | 按项目汇总 | `CONDITIONAL` | 项目关系基数与归属规则确认 |
| 组织维度 | 按历史团队汇总 | `BLOCKED` | 团队标识、变更前后值、有效时间和多团队分摊规则确认 |

即使候选指标的计算完成，也必须在质量门禁、贡献明细、版本清单和报表授权视图全部具备后才能形成 ADS 数据集。未满足条件的结果只允许在开发验证区标为“未验证”，不得伪装成正式日报或月报。

## 6. 质量与发布门禁

每个批次至少记录来源对象、读取上界、下界/重叠窗口、行数、重复数、拒绝数、RAW 校验摘要、抽取和入仓时间。下列任一情况阻断受影响的正式数据集发布：

- 来源键为空或重复，或稳定排序/水位无法复现；
- 当前态对象无法完成预定义字段、类型或项目关系校验；
- 快照不完整、批次失败或数据截止时间不满足发布要求；
- 指标依赖的状态映射、删除策略或团队历史仍为 `BLOCKED`；
- 新构建版本未通过质量、对账及发布清单校验。

发布遵循[总体架构](02-architecture.md)的版本构建和活动指针比较交换：先构建和验证完整版本，再原子切换活动发布；迟到完成的旧运行不得覆盖更新版本。SQL 报表账号只能读取批准数据集的授权视图，不能读取 RAW、内部 ODS 或任意版本表。

## 7. 业务与源系统确认清单

以下项目是开始真实接入编码前的必要输入，未确认时对应功能保持 `BLOCKED`：

1. `STORY.TYPE=0` 需求、`TYPE=1` 任务及 `PID` 父子关系已确认；仍需确认 `DEFECT.TYPE` 及其他类型取值。
2. 平台默认的创建、更新、实际开始/结束时间角色是否符合源系统实际语义，以及时区、精度、可空规则和可用索引。
3. 已发现粗粒度 `STATUS` 的候选语义为 0 未开始、1 处理中、2 已完成；缺陷样本中 `STATUS_CODE` 实际出现 `begin`、`close` 和数字字符串，不能直接采用列注释的纯数字映射。`NODE_STATUS` 查询显示需求/任务/缺陷流程状态按 `NODE_TYPE` 和项目配置变化，例如任务存在 `taskNot`、`taskClose`，需求存在 `not`、`done`，缺陷存在 `begin`、`checking`、`close`；因此正式映射必须按项目、对象类型和流程字典版本保存，不能把状态码做成全局常量。完成、关闭、重开、取消、归档、删除的正式映射，以及日志单值表示变更前还是变更后、同一时间的事件顺序，仍待确认。
4. 已确认 `DELETE_FLAG=0` 未删除、`1` 已删除；仍需确认删除对象在各指标统计总体中的排除规则，以及无物理删除时的同步和对账策略。
5. 项目与团队的关系基数、事件归属与期末归属规则；是否可提供带生效时间的团队历史。
6. 是否接受默认的每月第 5 个自然日 06:00、数据中心负责人审批、必要时业务负责人复核、最近 3 个月修订窗口，以及月报更正的对外显示规则。
7. 源库可接受的抽取窗口、索引/只读副本、来源 SLA、允许回读天数，以及正式 TLS 证书链和凭证引用方式。
8. 首个 SQL 报表账号的可见数据范围、数据保留期和下钻授权边界。

## 8. 首条接入验收条件

在不增加未批准依赖、不修改源库且不发布未验证指标的前提下，首条真实接入达到以下条件才可进入下一工作包：

1. 受控只读连接通过严格 TLS 验证，物理字段映射、索引与游标策略有可复查的确认记录。
2. 全量基线和至少一次重叠增量回读可幂等完成；批次、水位和行数可以审计，失败不推进检查点。
3. 对象当前态与接入日起快照的粒度、唯一性、来源和时间字段通过质量检查。
4. `CONDITIONAL` 和 `BLOCKED` 指标均按本契约隔离；没有完成状态映射时，系统不发布完成/关闭/周期/历史团队数据集。
5. 形成可重放的模型与数据集版本，且查询仅通过授权视图暴露已批准发布。

后续主题域接入复用上述平台契约和门禁，只新增来源适配、领域模型、映射、指标定义与黄金样本，不把 DevOps 特定规则沉入平台核心。
