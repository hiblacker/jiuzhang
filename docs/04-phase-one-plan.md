# 04 一期开发计划与工作分解

## 1. 排期前提

建议基线18周，另留2–4周外部依赖缓冲；这是在数据和人员按时到位条件下的估算，不是承诺上线日期。以项目启动周W1计算，未取得源接口/样本/指标审批前不直接转换为日历承诺。

人员假设：技术负责人/架构1、平台后端2、前端1、数据开发2、测试1；业务负责人、源系统和报表负责人、运维安全按阶段参与。人数不足时优先缩减指标和页面范围，不能同时保持全部范围与工期。

## 2. 里程碑和退出条件

| 阶段 | 周期 | 主要成果 | 退出门禁 |
|---|---|---|---|
| M0 需求与数据盘点 | W1–W2 | 数据协议、指标口径、报表连接方案、容量基线 | 源样本及历史可用性已确认；P0清单签字 |
| M1 技术PoC | W3–W4 | 同步/调度/SQL/发布/权限小闭环；组件版本矩阵 | 一条真实或受限测试链路跑通；不满足则调整范围 |
| M2 平台骨架与接入 | W5–W7 | 身份/凭证、元数据迁移、接入批次、原始存储、检查点 | 全量增量衔接、重试、同时间戳分页测试通过 |
| M3 加工与主题明细 | W8–W10 | SQL发布、运行适配、历史/事件、质量与补数 | 事件去重、重开、团队变更、迟到重算可复现 |
| M4 数据集闭环 | W11–W13 | 日/月模型、数据集版本、授权查询、下钻、报表联调 | 指标黄金样本全通过；发布和权限门禁通过 |
| M5 通用性与非功能 | W14–W16 | 销售合成主题、容量测试、故障注入、安全审计 | 不改核心新增主题；SLA/恢复目标经测试确认 |
| M6 试运行与交付 | W17–W18 | 并行验证、上线方案、运维手册、培训、验收单 | 连续10个工作日正常运行；月结回放和恢复演练通过 |

历史月结回放用于覆盖月指标，不能因为试运行未跨自然月而省略。可用历史必须来自可核验记录；合成样例用于算法验证，不代替真实对账。

## 4. 开发顺序与关键路径

先定义契约和样本，随后用一条纵向小链路验证技术，不先完成所有管理页面。

关键路径：源权限/历史确认 → PoC → 增量可靠性 → 主题历史 → 日月指标 → 发布/权限 → 报表验收。

可并行：API契约确认后的前端页面；合成黄金样本；运维环境与日志；已确认业务对象的模型开发。未经确认的源数据能力不得成为代码中的默认事实。

## 5. 每周与每个工作包的完成定义

每周评审演示可运行增量、数据对账、未决事项和风险；不是只报代码量。

工作包完成必须同时包含：实现、自动化测试、配置样例、迁移或回滚策略、权限检查、日志、文档更新、Git提交。涉及数据逻辑时额外包含样本输入、预期结果和边界场景。

所有功能从DRAFT进入REVIEW再进入RELEASED；生产SQL变更须绑定版本和审批，禁止直接在生产控制台改SQL而不回写Git。

## 6. 一期交付清单

应用源码与迁移；脱敏配置和部署说明；固定版本/许可证清单；接入与加工任务定义；主题SQL及样本；数据集契约；报表连接示例；质量/安全/性能报告；试运行对账；恢复演练；运维手册；业务验收单。

当前仓库已完成设计/调查基线、合成 POC-01 和 PLT-01 第一切片；其余工作包状态、执行顺序与出口条件见[后续规划与里程碑](21-next-milestones.md)。
