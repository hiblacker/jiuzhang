## 与原方案的具体取舍

1. 正式 MySQL 接入采用既有 MySQL CLI 的单只读事务读取，由 Node Worker 执行；未把 SeaTunnel 合成 PoC 冒充正式接入。该实现验证了整库一致读取、保真、覆盖及失败重新快照。CLI 只接收程序生成且标识符受控的 SQL。
2. 本地后台日历由平台单一驱动；外部调度可使用 `external` 模式调用同一认证入口。DolphinScheduler 正式产品适配没有完成，也不与本地驱动同时启用。
3. dbt 采用固定 Python v1：Core 1.11.15 / Postgres 1.11.0，原 PoC 锁保留。控制元数据和候选表目前在同一 PostgreSQL 内以 Schema/角色隔离，未完成物理分库。
4. 对 API 部分页，封存的响应可离线重解析；缺失页须重新按批准时间范围采集。不把缺页恢复或不稳定分页解释为完整时点快照。
5. 当前每日数据库默认全量；CDC、未经证明的增量、Iceberg、多引擎、在线 SQL IDE 和完整治理套件不在本次本地交付中。Excel 指 xlsx，旧 xls 未准入。真实 API 与实际交付目录尚未提供，已完成通用实现和合成验收。
