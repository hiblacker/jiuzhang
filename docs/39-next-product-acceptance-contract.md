# 下一批产品契约与验收清单

状态：建议契约，尚未实现；配套 [38 号方案](38-next-product-implementation-plan.md)。以下字段、资源名和接口是新增设计，不表示现有 API 已支持。实现先检查现有契约，能扩展则复用。

## 1. 配置与执行资源

| 对象 | 建议最小字段 | 约束 |
|---|---|---|
| 执行环境 | ID、名称、Worker 能力、在线状态、配置协议版本 | 只展示管理员登记的资源；项目授权与 Worker 自身边界同时生效 |
| 资源引用 | 目录根/网络目标/凭证引用、所属环境、允许项目 | 页面只能选引用及受限相对目录；密钥和宿主绝对路径不回传 |
| 来源配置版本 | sourceId、version、kind、resourceRefs、普通连接/解析参数、摘要、提交人 | 保存后不可改写；凭证只引用；旧任务绑定旧版本 |
| 测试/发现任务 | requestId、projectId、source/configVersion、状态、inventoryVersion、脱敏结果 | 同一请求可重放；由 Worker 限时执行；成功连接不等于全表接入完成 |

来源表单保存后先为草稿，测试/发现通过且范围确认后激活对应计划。Worker 不支持的配置协议直接拒绝，不能回退到任意本地默认值。高权限字段变更重新执行资源授权校验。

Worker 按执行环境、能力和配置协议领取任务，领取响应固定来源配置版本及摘要；凭证引用在本地解析。这样新增已授权来源无需修改进程启动时的 profile 列表。迁移期间保留旧注册表任务协议，新任务显式标记协议版本；每次领取和发布都校验项目授权，不能将全局 Worker 身份等同于资源无限授权。

## 2. 刷新计划和输入选择

### 2.1 固定运行内容

刷新计划至少包括 `datasetId`、`planVersion`、`modelVersion`、`timezone`、`schedule`、`inputSelectors`、`deadline`、`latePolicy` 和 `publishMode`。输入选择器必须指明来源、对象、交付窗口、允许修订、完整性要求及跨源时点容差。

构建幂等键由“刷新计划版本 + 业务窗口 + 固定模型版本 + 有序输入资产版本集合”生成。相同输入重复回执不产生新构建；同日更正产生新集合。记录每个输入的业务窗口、实际采集时点及完整批次，禁止只存一个模糊的“最新”标志。

同源 MySQL 多表默认选同一 COMPLETE 系统批次；文件包选同一闭合交付版本；API 仅选择已完成接收/解析且契约允许的版本。配置允许跨源同业务日时，仍分别保留来源实际时点。

### 2.2 运行投影

建议业务状态：等待输入 → 构建中 → 质量检查 → 待发布 → 已发布；另有失败、已取消和需人工确认。它们是现有执行/模型/发布状态的产品投影，不能另建一套与数据库事实脱节的“成功”标记。

等待截止后创建异常并保留具体缺项；迟到策略决定继续等待、需要人工补算或创建新修订。不把目录失联解释为合法空数据。不具备历史快照的来源仍遵守“过去不可补造”规则。

数据集状态分别表达：

- **可查询性**：是否有可读且获授权的已发布版本。
- **新鲜度**：实际数据截止时间是否满足当前契约。
- **当前任务**：新一轮正在等待、运行或失败。

因此可以同时出现“旧版可查询、数据已过期、本轮失败”，不会因一轮失败丢失旧版，也不会把旧版标成今日已更新。

### 2.3 发布规则

默认人工发布。自动发布只能作用于负责人已批准的模型/契约/策略版本，必须同时满足输入完整、质量门禁、权限兼容、当前 release 及陈旧输入检查。首发、破坏性结构变更、模型契约改变或授权不兼容转人工处理。

刷新计划的业务操作责任人和服务执行身份分别保存；后台任务不能借用全局管理员权限绕过项目授权。角色/资源被撤销后，新领取和发布时重新校验；运行中的 SQL 按已有租约/取消语义处置。

## 3. 质量、依赖与数据服务

- 规则包含稳定 ID、版本、检查对象/字段、类型、阈值、阻断级别和说明；结果包含输入/构建/规则版本、实测值、是否通过和有限的受控问题样本。
- 支持字段类型、非空、唯一、枚举、范围、引用完整性、行数变化和新鲜度。规则未定义时显示未配置，不能显示检查通过；空数据的合法性由交付及模型契约决定。
- 依赖关系来自固定模型契约、输入 manifest 和 dbt manifest，关联实际构建及 release。先提供节点级依赖和受影响数据集列表；动态 SQL 无法解析时显示未知。
- 数据集详情和查询结果携带模型/契约版本、release、权限版本、各来源截止时间。统计和下钻保持同一 release；多次请求通过显式 release 固定版本。
- 为报表提供服务身份和可复制的请求样例。新增范围、集合和排序操作按字段类型/授权白名单校验；超出能力明确拒绝，不拼接任意表达式。CSV 导出继续保持公式注入防护和数值保真。
- 浏览器用户使用可撤销会话，服务 Token 有独立生命周期。敏感凭证不写入浏览器存储、URL、日志或 Git。

## 4. 异常与运行观测

异常标识由来源/数据集、计划版本、逻辑窗口和错误类别构成。重试 attempt 作为同一异常的观察记录，避免每次轮询生成新事项。状态至少为待处理、已确认、已恢复；人工确认不等于业务恢复。

处理动作给出影响范围、目标窗口、原件/输入版本和原因。恢复必须关联新的成功执行及对应完整性/质量检查；仅按下“重试”不能关闭异常。发布受阻、Worker 失联和磁盘预算不足各有独立原因。

本批默认提供站内异常和查询审计。外部通知在已有批准渠道上扩展；不假定已经存在企业微信、邮件或其他通道。

## 5. API 交付范围

建议在现有 `/api/v1` 命名空间增加以下能力，最终路由以正式契约为准：

| 能力 | 请求/响应要点 | 复用位置 |
|---|---|---|
| 会话与当前身份 | 登录/退出、项目、角色、可执行动作、过期/撤销 | 现有身份和项目成员；增加浏览器会话 |
| 项目执行资源 | 可用能力、资源引用、配置协议 | 扩展 Worker 注册表和能力领取 |
| 来源配置及测试发现 | 版本、资源引用、202 任务 ID、脱敏结果、库存版本 | source、lake inventory、执行租约 |
| 来源/资产/运行搜索 | 有界分页、稳定排序、项目过滤、状态/日期/对象筛选 | 扩展现有列表，不再静默截断 |
| 模型目录及包 | 批准 Git 源、固定提交、契约、不可变包引用 | 现有模型版本、bundle 校验和 dbt Worker |
| 数据集刷新计划 | 输入规则、版本、窗口、发布策略、暂停/补算 | 现有日历、构建队列、发布检查 |
| 质量与异常详情 | 原因、测量值、影响资产、责任人、恢复关联 | 构建结果、审计、运行记录 |
| 数据服务及查询审计 | 字段说明、授权、调用示例、查询结果版本和审计 | 现有 query/export/policy |

分页与错误模型形成统一 DTO/契约，再交给前端；状态枚举和动作权限由后端提供，不由前端根据字符串猜测。

## 6. 必须通过的端到端案例

| ID | 场景 | 通过标准 |
|---|---|---|
| A01 | 负责人邀请成员；成员登录、切换项目、退出或被停用 | 项目和菜单正确；停用会话不能继续操作或取数 |
| A02 | 在已授权目录新增每日 CSV 来源 | 不编辑服务器 JSON；目录扫描、规则生效、资产可查；输入保持原件 |
| A03 | MySQL 全库发现及新计划 | 全表清单和例外可见；新增表须确认；预检不运行整库抽取 |
| A04 | xlsx、JSON、Parquet 和模拟 REST 接入 | 逐格式契约可配置；精确值/空值保持；错误可解释；API 凭证不随 next-link 越界 |
| A05 | 交付缺失、半写、合法空包、迟到和目录断连 | 状态准确、按规则等待；恢复后重读闭合版本，不把未交当空交付 |
| A06 | 登记 Git 模型并通过选择资产构建 | 未提交 SQL 不执行；包和输入摘要正确；无需手填内部 ID；不用重建应用镜像 |
| A07 | 同源多表自动刷新，某表或外部依赖晚到 | 多表来自同一完整系统批次；必需输入未齐不构建/发布；到齐后固定输入 |
| A08 | 同一窗口重复回执、重启、旧 Worker 回执 | 仅生成一个相同输入构建；租约和完成状态正确；旧回执不能推进发布 |
| A09 | 已发布后收到更正包或模型变化 | 更正生成新版本；模型/契约变化按策略进入人工确认；旧版可追溯 |
| A10 | 唯一性/引用/类型/新鲜度规则失败 | 展示具体规则和测量值；阻断发布；旧版查询仍可用且过期状态真实 |
| A11 | 开启已批准模型的自动发布后发生竞争或权限撤销 | 当前 release 条件更新；旧输入不覆盖；授权撤销后不自动发布 |
| A12 | VIEWER 查询/导出，伪造其他项目 ID 或未授权列 | 后端拒绝越权；查询、导出、详情权限一致；审计含 release/策略版本 |
| A13 | 新旧版本间连续分页、查询与导出 | 固定 release 不混版本；数值精度及字段顺序保持；超限明确拒绝 |
| A14 | 来源/资产超过一页，筛选为空或网络请求失败 | 全量可分页查找；不会把截断结果显示为全量；空和错误可区分 |
| A15 | 每日失败、重试成功、旧数据已过期 | 一个可追踪异常包含多次尝试；真实恢复才关闭；首页显示受影响数据集 |
| A16 | 从一期安装升级到本批，随后执行恢复验证 | 旧迁移校验和不变；既有 157 表登记、原件引用和真实 release 可用 |
| A17 | 无真实源凭证的全新合成环境运行 CI/浏览器测试 | 测试可独立复现；没有后台访问真实 MySQL、真实 API 或发送外部通知 |
| A18 | 一位未参与开发的使用者完成三条主流程 | 依手册操作；记录卡点并修复关键阻碍；人工操作验收状态单独记录 |

人工使用验收、真实目录/API 和真实连续窗口尚无证据时分别标为待验收。自动化通过不自动勾选 A18 或生产稳定性。

## 7. 交付证据

每个工作包交付代码、契约/迁移、合成样例、验收记录、运行说明和本地提交；新增依赖另附精确版本与许可记录。验收记录区分“本次执行、复用历史、未执行、跳过”，列出新旧版本和实际提交 SHA。

本批完成报告必须回答：谁可以独立使用、哪个真实来源/数据集已接通、哪些输入仍为合成、自动刷新运行了哪些窗口、发生过什么异常、如何恢复、哪些环境尚未部署。保留现有 37 号验收，不将其改写为本批的新证据。
