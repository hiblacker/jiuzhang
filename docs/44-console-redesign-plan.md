# 44 控制台界面重构方案（调研 + 方案，待评审）

状态：**方案，未批准，未开发**。本文只做现状评估、同类产品调研与重构设计；不含代码改动。

配套：[产品可行性 §2.3 最小控制台信息架构](../docs/30-warehouse-product-feasibility.md)、[38 号 Vue 工作台建设记录](38-vue-console.md)、[41 号运行手册](41-product-workbench-runbook.md)、[42 号首次上手](42-first-run-walkthrough.md)、[MySQL 接入方案](43-mysql-ingestion-design.md)。

## 0. 结论先行

1. 当前界面的问题**不是组件库不好看**，而是**几乎没有设计层**：全站样式表只有 20 行（一个字体栈、一个文字色、一个三列网格、一个 `margin:16px 0` 的万能间隔类）。Naive UI 默认外观直接外露，因此"像半成品"。
2. 最刺眼的三个具体问题是：**① 详情/质量/输入版本直接用 `JSON.stringify` 原文铺在弹窗里**；**② 状态用英文枚举纯文本显示（`COMPLETE`/`RAW_COMMITTED`/`MISSING_DELIVERY`）没有色彩与图标语义**；**③ 表格列宽自动分配导致内容截断（如通道名被截成 `test-e…`），且没有固定列、没有行操作区**。
3. 导航是 7 个扁平一级菜单，按"功能块"而非"用户任务"命名，且没有二级层级、没有面包屑、没有深链（刷新与分享都回到首页）。这与 [30 号文档已定的 6 个区域信息架构](../docs/30-warehouse-product-feasibility.md) 已经偏离。
4. 建议**保留 Naive UI**（ADR-010 已确认），只补设计令牌 + 组件规范 + 布局骨架，分 4 阶段小步重构；**不引入新的 UI 依赖**（新增依赖需许可与版本评审）。
5. **前置工程前提**：多数 `.vue` 文件把整个 `<template>` 压成一行（单文件数千字符），样式无法一致落地。阶段 0 必须先拆分组件，否则任何"视觉统一"都会被后续修改重新打散。

### 1.1 问题清单

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| 1 | 无设计令牌：无间距刻度、无字号层级、无语义色、无圆角/阴影规范 | `apps/console/src/style.css` 全文 20 行 | 全站观感不一致，改一处不能全局生效 |
| 2 | 万能类 `.gap{margin:16px 0}` 承担几乎所有间距 | 全站模板 | 密度不可控，卡片与表格节奏呆板 |
| 3 | 详情用裸 JSON | `ModelWorkspace.vue`（质量/输入版本）、`RunCenter.vue`（执行详情）、`IngestionManager.vue`（配置对比） | 用户看不懂、无法扫描、信息架构缺失 |
| 4 | 状态无色彩语义 | 资产目录 `状态` 列、运行中心 `state` 列均为纯文本 | 危险状态不显眼，需要逐字读英文枚举 |
| 5 | 枚举裸露英文 | `RAW_COMMITTED`、`PARSED`、`MISSING_DELIVERY`、`TEST`/`PRODUCTION` | 中文用户需要查文档 |
| 6 | 表格无列宽策略、无固定列、无行操作区 | 截图 04/05/10：名称被截断，操作靠文本链接 | 内容读不全，找不到能做什么 |
| 7 | 数字不是等宽、未右对齐 | 行数/字节/金额列 | 无法纵向比较，精度感知差 |
| 8 | 导航扁平、无分组/二级/面包屑、无深链 | `App.vue` 单层 `n-menu`，页面状态只在内存 `page` ref | 刷新/分享丢失位置；7 项已接近上限 |
| 9 | 极端依赖弹窗 | 接入向导、模型绑定、发布、授权、详情全是模态框 | 向导在 800px 弹窗内挤压；流程难以回看 |
| 10 | 空/加载/错误/无权限四态不统一 | 只有 `n-empty` 默认图标 + 顶部 `n-alert`；错误文本形如 `操作未完成（INVALID_...）` | 用户不知道是系统问题还是自己填错 |
| 11 | 响应式与可访问性几乎未设计 | 仅 850px 一个断点；无暗色；无显式焦点样式 | 键盘用户与大屏/小屏体验差 |
| 12 | 登录页缺乏产品识别度 | 居中窄卡片 + 默认绿按钮 | 第一印象弱 |

## 2. 同类产品调研

**调研方式与限制**：本轮**在线搜索工具不可用**（搜索端点鉴权失败），因此调研由两部分组成：① 仓库内已完成的同类产品研究（[30 号 §6](../docs/30-warehouse-product-feasibility.md)，含固定提交与许可证据）；② 模型对同类产品的既有认知。凡属②的判断**本轮未逐条复核**，采纳前需按 §5.3 的清单核实。仓库内已明确的事实：Airbyte 根许可为 ELv2，**不进入默认交付组合**。

### 2.1 仓库内已有的产品结论（可直接引用）

| 产品 | 可借鉴的模式 | 对界面的含义 |
|---|---|---|
| Dagster | 以"资产"连接持久结果、生产逻辑与依赖 | 数据集详情要能从"结果"追到输入/模型/质量/运行，首页不能只堆任务成功数 |
| SQLMesh | 变更前生成计划：直接/间接影响与补数范围 | 发布、映射变更、范围变更都要"先看影响再确认"的预览页 |
| NiFi | 发现/读取/流转分步，队列与反压可见 | 接入向导的"连接→测试发现→交付计划"三步是对的，应保留并强化回看 |
| dlt | 声明式描述资源、分页、字段；推断结果需人工确认 | 探测/推断结果必须是"可编辑确认页"，不能自动生效 |
| OpenMetadata / DataHub | 资产详情围绕字段、负责人、质量、血缘、语义 | 资产详情页签结构（概览/结构/数据预览/批次与责任人） |
| DataSphereStudio / Taier | 统一项目、统一运行 ID、统一错误与发布 | 全站共享同一对象 ID 与状态词表，不按组件名分菜单 |

### 2.2 同类产品的界面共性（模型认知，待核实）

| 模式 | 常见做法 | 对应到九章 |
|---|---|---|
| 连接/向导 | 分步向导（来源 → 认证 → 对象选择 → 计划 → 确认），每步可回看，最后一步给出"将要发生什么"摘要 | 保留现有 3 步，增加"确认页"与返回任意步骤 |
| 对象选择 | 表/字段多选带搜索、类型徽标、"全选/仅新增"、主键与行数提示 | 范围确认页（[43 号方案 §3.1](43-mysql-ingestion-design.md)） |
| 数据浏览 | 表格抽样预览 + 列类型/注释 + 行数/截断提示 + 一键复制 SQL（Metabase/Superset 常见） | 资产详情"数据预览"页签；不提供在线任意 SQL |
| 运行与运维 | 运行列表带状态色彩、持续时间、重试/取消、日志折叠面板、按状态/时间过滤 | 运行中心改为"状态色 + 耗时列 + 抽屉详情" |
| 发布/审批 | 变更差异视图 + 影响清单 + 必填原因 → 确认发布 | 已有发布原因，补"差异/影响"视图 |
| 权限 | 行列授权用"身份 × 字段 × 条件"矩阵，展示当前生效版本 | 授权弹窗改为矩阵 + 版本对照 |
| 目录与搜索 | 全局搜索（跨系统/连接/通道/数据集/资产）、最近访问 | 阶段 3 增加顶栏搜索与最近访问 |
| 设计系统 | 令牌化（颜色/字号/间距/圆角/阴影）+ 语义色 + 密度可切换 + 暗色 | §3.2 的令牌层 |

### 2.3 可借鉴的 6 条原则（本方案的判断）

1. **导航按用户任务分组**，不按组件或功能块命名；与 30 号文档的 6 区域一致。
2. **列表 → 详情 → 抽屉三层层级**：列表可扫描、详情可深链、操作在抽屉里完成。
3. **状态 = 颜色 + 图标 + 中文词**，英文枚举只作为 tooltip 补充。
4. **向导分步且可回看**，最后一步给出"将要发生什么"的确认摘要。
5. **数据网格是核心组件**：列宽策略、固定列、行操作区、等宽数字、密度切换、键盘可达。
6. **空/加载/错误/无权限四态显式设计**，错误必须给出"人话 + 错误码 + requestId"。

## 3. 重构设计

### 3.1 信息架构（对齐 30 号文档）

```text
顶栏：项目选择 · 全局搜索 · 环境/Worker 状态灯 · 账号
侧栏（一级，按任务分组）
  1 工作台        待处理异常 · 数据集新鲜度 · 最近发布 · 我的项目
  2 数据接入      系统/实例 · 连接与通道 · 交付计划 · 批次与错误
  3 数据开发      数据集 · 模型版本 · 构建与质量 · 刷新计划
  4 运行运维      执行窗口 · 异常 · 查询审计 · 重试/取消
  5 数据资产      资产目录 · 结构 · 数据预览 · 责任人
  6 发布与管理    发布记录 · 行列授权 · 成员与服务身份 · 环境与资源
```

- 二级导航用**左侧展开或页面内页签**（保持在同一个页面语义里），不新增弹窗。
- **深链**：路由用 `#/projects/:id/:area/:sub/:entityId`（或 query），刷新保持当前位置，可分享给同事。
- 保留现有对象 ID 与状态词表，避免同一概念出现两套名称。

### 3.2 视觉语言（令牌 + 语义色）

用 Naive UI 的 `themeOverrides` 注入，不新增依赖：

| 令牌组 | 建议 |
|---|---|
| 字号 | 12 / 13 / 14(正文) / 16 / 20 / 26；表格正文 13，紧凑模式 12 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32；页面内边距 24–32，卡片内边距 16–20 |
| 圆角 | 4(输入/按钮) / 8(卡片) / 12(弹窗) |
| 语义色 | 成功(完成/已发布) · 进行(运行中) · 警告(迟到/待确认) · 危险(失败/已过期) · 中性(未开始/已暂停) · 信息 |
| 字体 | 保留 `Inter, PingFang SC, Microsoft YaHei`；数字一律 `font-variant-numeric: tabular-nums` 并右对齐 |
| 密度 | 表格提供"舒适/紧凑"切换（数据密集页默认紧凑） |
| 暗色 | 阶段 3 可选；令牌层先行，暗色只是换令牌值 |

**品牌色**：现为 Naive UI 默认绿。建议确定一个品牌主色（与"可信、可追溯"的定位一致），并同步登录页、图表与状态色，避免"默认主题"观感。

### 3.3 组件规范（要做的核心 8 个）

| 组件 | 责任 | 替换掉的现状 |
|---|---|---|
| `PageHeader` | 标题 + 面包屑 + 主操作 + 次要操作 | 现在 `header` 只有标题与两个按钮 |
| `StatusTag` | 状态 → 颜色/图标/中文/原值 tooltip 的**唯一映射表** | 各页面自己写文本 |
| `DataGrid` | 列宽策略、固定列、行操作、空态、密度、分页、导出 | `n-data-table` 裸用 |
| `DetailDrawer` | 实体详情（字段列表 + 分区 + 折叠原文） | 弹窗 + 裸 JSON |
| `DiffView` | 变更差异/影响预览（配置、映射、发布） | 裸 JSON 对比 |
| `Wizard` | 分步向导（步骤状态、可回看、确认摘要） | 弹窗内 3 步 |
| `AsyncButton` | 提交中/成功/失败/重复点击保护 | 各按钮自己 `busy` |
| `StatePanel` | 空/加载/错误/无权限四态统一 | `n-empty` + 顶部 alert |

配套规范：错误文案 = 中文说明 + `(错误码)` + 可复制的 `requestId`；字典集中维护（`COMPLETE→已完成`、`PARSED→已解析`、`RAW_COMMITTED→原件已落湖`、`MISSING_DELIVERY→应有交付未到` 等）。

### 3.4 关键页面的目标形态

| 页面 | 现在 | 目标 |
|---|---|---|
| 工作台 | 3 张等权卡片 + 2 张表 | 顶部"需要我处理"（异常/过期/待审批）优先，其次健康度与最近发布；数字带语义色 |
| 接入管理 | 系统列表 + 弹窗向导 | 系统/实例两级导航；通道列表带状态色、行操作区；向导全页或宽抽屉，含确认摘要 |
| 资产目录 | 元数据表 | 元数据表 + 行点击进详情（概览/结构/数据预览/批次），见 [43 号 §3.7](43-mysql-ingestion-design.md) |
| 运行中心 | 状态纯文本 + JSON 详情 | 状态色 + 耗时列 + 过滤条持久化 + 抽屉详情（摘要/时间线/日志摘要/原始 JSON 折叠） |
| 数据开发 | 数据集列表 → 弹窗绑定 → 构建表 | 构建列表带质量门禁摘要；发布前 `DiffView` 影响预览 |
| 数据服务 | 查询 + 弹窗授权 | 授权矩阵 + 版本对照；查询结果列头显示类型与脱敏标记 |
| 项目与设置 | 多种卡片混排 | 分组：成员/服务身份 · 环境与资源 · 模型仓库 · 危险操作；敏感操作二次确认 |
| 登录 | 窄卡片 | 品牌区 + 帮助入口（如何拿到邀请码）+ 明确错误提示 |

## 4. 实施阶段（小步、可回滚、每阶段可交付）

| 阶段 | 内容 | 前置/工作量（粗估，人日） | 验收 |
|---|---|---|---|
| 0 组件拆分 | 把单行 `.vue` 模板拆成组件与子组件；建令牌文件与组件目录；不改行为 | 无前置 · 2–3 天 | 现有浏览器验收保持全绿；无功能变化（截图 diff 允许外观变化但结构等价） |
| 1 令牌 + 状态 + 四态 | 接入 `themeOverrides`、`StatusTag`、`StatePanel`、词典（枚举中文化） | 阶段 0 · 2–3 天 | 全站状态有色彩与中文；空/无权限/错误有统一面板；错误含错误码与 requestId |
| 2 网格 + 抽屉 | `DataGrid` + `DetailDrawer` + `DiffView`，替换 4 个主要列表与其 JSON 详情 | 阶段 1 · 4–6 天 | 资产/运行/系统/数据集列表不再截断、可深链、详情可读；JSON 仅作折叠的"原始数据" |
| 3 向导 + 首页 + 路由 | `Wizard` 改造接入向导；工作台信息层级；URL 深链与最近访问 | 阶段 2 · 4–6 天 | 接入向导可回看有确认摘要；刷新/分享保持位置；首页突出待办 |
| 4 可选 | 暗色主题、图表（趋势/新鲜度）、全局搜索 | 阶段 3 · 5–8 天 | 需先决定是否引入图表依赖（许可与版本评审） |

**每个阶段的共同验收**：① `npm run build --prefix apps/console`（含类型检查）；② 现有 Playwright 浏览器验收不变绿即回滚；③ 新增视觉基线截图（同一套合成数据夹具，见 §1 的方法）作为回归对比；④ 关键任务路径用时可测（如"新建文件通道"从 6 分钟降到 3 分钟以内——目标值需人工试用确认）。

## 5. 风险、依赖与未决问题

### 5.1 风险

- **单行模板是最大障碍**：不先拆分，任何令牌与组件规范都会被下一次修改打散；阶段 0 必须做，且必须"零行为变化"。
- **弹窗改抽屉/路由会改变交互习惯**：需保留键盘与快捷键，且不可破坏现有 `aria-label`（浏览器验收依赖它们）。
- **前端依赖已冻结**：`lucide-vue-next 1.0.0` 已被上游标记弃用（[38 号记录](38-vue-console.md)），图标迁移需重新核对版本与许可；本轮方案不新增依赖。
- **主包 633 KB**：继续加组件前应先做模块拆分（现有构建已提示）。

### 5.2 依赖

- 后端接口不因界面重构而变化；若为"数据预览""映射对照"新增接口，属 [43 号方案](43-mysql-ingestion-design.md) 的范围，界面只消费其契约。
- 浏览器验收脚本（`tests/product-browser.mjs`）依赖界面标签文本；重构必须在同一提交内同步更新断言，否则 CI 会红。

### 5.3 需要决策/确认的问题

1. **品牌主色**与是否要暗色主题。
2. **目标视口**：是否只需 Windows 桌面（1920/1440），是否需要窄屏（≤1280）可用。
3. **数据密度偏好**：默认舒适还是紧凑；是否需要密度切换。
4. **图表**：是否需要趋势/新鲜度图表；若需要，引入哪个库（需许可与版本评审）。
5. **可访问性等级**：是否要求键盘全可达 + WCAG AA 对比度。
6. **调研复核**：§2.2 的同类产品共性属模型认知，采纳前用一次真实产品走查（Metabase / Superset / Airbyte / dbt Cloud / Dagster 的公开演示或文档）逐条确认，并把结论补进本文。
7. **是否先做 A18 人工试用**：建议在阶段 1 之后拉一位未参与开发的使用者按 [42 号手册](42-first-run-walkthrough.md) 走一遍，避免把"看不懂界面"混进"功能缺陷"。
